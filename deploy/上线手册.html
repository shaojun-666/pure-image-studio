从买服务器到 HTTPS 上线

这个项目本身已经是「能上线」的状态——Dockerfile、compose、nginx、定时备份、健康检查全都写好了。所以你要做的不是搭部署，是买机器、填 5 个变量、跑 3 条命令。下面是按你的选择定好的完整路径。

轻量服务器 · 2C4G Ubuntu 22.04 local 本地卷 免域名 · 免备案 预计 2–3 小时
服务器
香港，或大陆节点换端口
大陆 IP 的 80/443 要 ICP 备案 7–20 工作日，来不及；换个端口（8080）就能绕开这条线。香港则完全不用备案。
图片存储
local 本地卷
省掉 OSS bucket、RAM 子账号、桶策略、CDN 绑定四件事，演示完全够用。compose 原生支持。
数据
全新 seed + 拷缩略图
干净库，再把本机 37 张风格图传上去。不拷的话 seed 只写渐变占位图，风格栏会很难看。
不用买域名

临时演示用公网 IP + HTTP 就够了，登录也正常——Auth.js 只在 https: 下才挂 __Secure- 前缀的 cookie，走 HTTP 会自动降级成普通 cookie，这一点是查过 @auth/core 源码确认的，不是猜的。省掉域名钱、省掉实名认证的等待，也整个跳过第 06 步。代价仅仅是地址栏没有小锁，浏览器会标「不安全」——课堂演示无所谓。

00

买机器，记下公网 IP

  1. 买一台服务器。镜像 Ubuntu 22.04（24.04 也行，应用跑在容器自带的 Debian 里，跟宿主版本无关），配置 2 核 4G，系统盘 40G 起。已经买成 2G 的不用退——见下面。
  2. 不用买域名。在控制台记下这台机器的公网 IP，后面所有地方都用它。
  3. 安全组放行 22，以及你选定的 HTTP 端口（香港用 80，大陆节点用 8080）。
为什么推荐 4G 内存

不是随便定的：Next 构建、Postgres、内嵌 worker 挤在同一台机器上，2G 会在 docker build 阶段被 OOM kill，而且报错很难看出是内存问题。

已经买了 2G 的：能跑，但必须先加 swap

要分清楚炸的是哪一步。运行够用——db + app + worker + nginx 加起来约 1G；构建不够——next build 峰值常到 1.5–2.5G。用系统盘划 4G swap 就能扛过去，代价是慢。操作见第 01 节，构建时长的影响见第 04 节。

已经买了阿里云上海（或别的大陆节点）？也能用

备案卡的是 80 和 443 这两个端口，不是整台机器。换个端口就不碰这条线：HTTP_PORT=8080，访问 http://你的公网IP:8080。安全组记得一并放行。

大陆节点对课堂演示其实更稳——延迟低、路由不抖，而且调阿里云百炼是同城同云。这个项目的 .npmrc 和 Dockerfile 本来就走了国内 npm 镜像，在大陆机器上构建不会卡。

反过来，如果你用香港 / 海外节点，上面这些都不用管——那里根本不涉及备案。

01

服务器初始化

SSH 上去。先按需加 swap，再装 Docker，然后务必配镜像加速。

服务器执行 —— 2G 内存必做，4G 可跳过

# ★ 2G 机器漏了这步，第 04 节的 docker build 会被 OOM kill
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

free -h   # 确认 Swap 那行有 4.0Gi

服务器执行

# 装 Docker。大陆节点用带 --mirror Aliyun 的那行，直连官方源会很慢
curl -fsSL https://get.docker.com | sudo sh
curl -fsSL https://get.docker.com | sudo sh -s docker --mirror Aliyun   # ← 大陆节点用这行

sudo usermod -aG docker $USER && newgrp docker

# ★ 不配这行，拉 docker.io 的镜像会超时
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{ "registry-mirrors": ["https://docker.m.daocloud.io"] }
EOF
sudo systemctl restart docker

docker run --rm hello-world    # 出 Hello 就算过
验证点

docker compose version 有输出。官方脚本会把 compose 插件一起装上，不用另外装。

02

把代码弄上服务器

这个项目现在不是 git 仓库

部署手册里的 git clone 你得先有仓库。两条路选一条，源码只有 2.3M，怎么传都快。

路线 A · 建私有仓库（后续 git pull 升级更顺）

# 本机，项目根目录
git init && git add -A && git commit -m "首次提交"
git remote add origin <你的私有仓库地址>
git push -u origin main

# 服务器
mkdir -p /opt && cd /opt
git clone <你的私有仓库地址> aigc

路线 B · 直接传文件（不碰 git）

# 本机，项目根目录
tar --exclude=node_modules --exclude=node_modules.broken \
    --exclude=.next --exclude=.next-build --exclude=.data \
    --exclude=.env -czf aigc-src.tgz .
scp aigc-src.tgz root@<服务器IP>:/tmp/

# 服务器
mkdir -p /opt/aigc && tar -xzf /tmp/aigc-src.tgz -C /opt/aigc
推之前先看一眼

走路线 A 的话，git push 前跑一次 git status，确认列表里没有 .env。你的百炼 key 就在那个文件里。.gitignore 已经盖住了 .env、.data/、node_modules，正常不会漏，但值得花三秒确认。

03

填 .env

服务器执行

cd /opt/aigc
cp .env.production.example .env
chmod 600 .env

# 生成三把钥匙，把输出填进 .env
openssl rand -base64 32    # → AUTH_SECRET
openssl rand -hex 24       # → CRON_SECRET
openssl rand -hex 16       # → POSTGRES_PASSWORD

整个文件里只有 5 项不填容器会直接拒绝启动（这是模板故意设计的：宁可起不来，也不要带着半套配置对外服务）。

变量填什么
NEXT_PUBLIC_SITE_URLhttp://你的公网IP
大陆节点：http://你的公网IP:8080
CDN_BASE_URLhttp://你的公网IP/api/files
大陆节点：http://你的公网IP:8080/api/files
HTTP_PORT香港留默认 80；大陆节点改 8080。nginx 容器内部照旧听 80，只改这个映射
POSTGRES_PASSWORD上面 openssl rand -hex 16 的输出
AUTH_SECRET上面 openssl rand -base64 32 的输出
CRON_SECRET上面 openssl rand -hex 24 的输出

然后按本地存储改这两处：

STORAGE_DRIVER=local      # 模板默认是 oss，改成 local
                          # OSS_* 那一整段全部留空，不用管

最后补上模型 key——这一项漏了，演示时一张图都出不来：

DASHSCOPE_API_KEY=<你现在本机 .env 里那个百炼 key>

# 只在灌数据那一次用得上，跑完可以删掉这两行
SEED_ADMIN_EMAIL=admin@aigc.local
SEED_ADMIN_PASSWORD=<自己定一个强密码>
CDN_BASE_URL 是最容易填错的一项

它必须是你自己的访问地址加 /api/files——用 IP 就是 http://你的公网IP/api/files。填成 OSS 域名不会报任何错，只会让所有 public/* 的图 404——风格栏、探索页全裂，而日志里一片干净。

建议顺手改一个值

WORKER_CONCURRENCY=2。百炼对这个账号的 QPS 卡得很紧，并发调高会整批撞 429。本机跑示例图时并发 3 就失败过，最后是老实串行跑完的。

04

构建并起服务

服务器执行

cd /opt/aigc
./deploy/scripts/deploy.sh --seed

这一条命令做五件事：构建三个镜像 → 起数据库并等就绪 → 跑迁移 → 起应用和网关 → 等健康检查。带上 --seed 会再灌一次初始数据（管理员、模型目录、风格、提示词、探索内容）。

第一次要等 10–25 分钟

要拉 postgres / nginx 基础镜像，还要在容器里装一遍依赖。中途没有输出是正常的，别以为卡死了去 Ctrl-C。第二次之后有层缓存，几分钟就完。

2G + swap 的机器会更久：15–40 分钟。构建在疯狂换页，慢是必然的，不是卡死。怎么判断它在干活：另开一个 SSH，free -h 看 swap 在减少、docker stats 有 CPU 占用，就说明正常。

万一还是挂了，日志里会出现 Killed 或 signal: killed——那就是 OOM。把 swap 加到 8G 重试：sudo swapoff /swapfile && sudo fallocate -l 8G /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile。再不行就改走「本机 build 好、把镜像传上去」那条路，跟我说一声。

验证

docker compose ps
# db / app / nginx / cron 都是 Up，migrate 是 Exited (0)

curl -s localhost/api/health
# {"ok":true,...,"db":"up"}

curl -sI localhost | head -1
# HTTP/1.1 200 OK
到这里 http://你的公网IP 已经能开了

先去浏览器打开 http://你的公网IP，确认首页出得来、能注册登录。到这一步演示其实已经能跑了，剩下的只是把图准备好。

05

把风格缩略图拷进去

seed 只会给缺图的风格写渐变占位图。演示风格栏不能是 37 个色块，把本机那批真图覆盖上去——一共 3.1M，秒传。

本机执行

cd "D:\Desktop\ai生图网站"
tar -czf thumbs.tgz -C .data/storage public
scp thumbs.tgz root@<服务器IP>:/tmp/

服务器执行

cd /opt/aigc
tar -xzf /tmp/thumbs.tgz -C /tmp
docker compose cp /tmp/public/. app:/app/.data/storage/public/
不用重启服务

刷新页面就能看到新图。图片地址现在带 ?v=<mtime> 版本号，文件换了 URL 就跟着换，浏览器会自动取新的——不会再出现「明明换了图却还是显示老图」那种事。

验证

打开 http://你的公网IP/zh/generate，风格栏 37 张应该都是真图。再翻一眼探索页的 12 张封面。

06

（可选）换上域名和 HTTPS

演示用不上，跳过不影响

这一步只有在你买了域名之后才有意义——Let's Encrypt 不给裸 IP 签证书。所以如果你只做课堂演示，整节跳过，直接看第 07 步。等到想正式挂出去时再回来做。

有了域名之后，nginx 配置里已经留好了 certbot 的 HTTP-01 挑战入口，不用买证书，直接签就行。

服务器执行

sudo apt install -y certbot

# 挑战目录：nginx 把它挂成了 /var/www/certbot（只读），宿主机这边写进去
mkdir -p /opt/aigc/deploy/certs/acme

sudo certbot certonly --webroot -w /opt/aigc/deploy/certs/acme \
  -d 你的域名 -d www.你的域名 \
  --agree-tos -m 你的邮箱 --no-eff-email

# 证书改名丢进 deploy/certs/
cp /etc/letsencrypt/live/你的域名/fullchain.pem /opt/aigc/deploy/certs/fullchain.pem
cp /etc/letsencrypt/live/你的域名/privkey.pem   /opt/aigc/deploy/certs/privkey.pem
chmod 600 /opt/aigc/deploy/certs/privkey.pem

# 叠一层 TLS 覆盖层起来（80 只做跳转，443 带 HSTS）
cd /opt/aigc
docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d
验证

https://你的域名 打开是绿的，http:// 自动 301 跳过去。然后把保险箱里那个 SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD 从 .env 删掉，重启一次。

Let's Encrypt 证书 90 天到期

演示只有几天，其实不续也无所谓。想续就加一条 crontab：0 4 * * 1 certbot renew --quiet && docker compose -f /opt/aigc/docker-compose.yml -f /opt/aigc/docker-compose.tls.yml restart nginx。

07

演示当天

最大的现场风险不是服务器，是出图速度

百炼对这个账号的 QPS 卡得很紧，本机生成一张示例图要等十几秒，现场网络再加一层就不好说了。5 分钟的演示经不起一次「转圈转到超时」。

两个保险，建议都做：

  • 提前跑几张图存进历史。演示时如果实时生成慢，直接翻「历史」页讲结果，节奏不会断。
  • 录一段 30 秒的完整出图屏。这是最后一道保险，网络彻底不给力时直接放录像。

卡住了看这里

症状八成是这个
app 反复重启docker compose logs app | tail -50。多半是 .env 少填了必填项——compose 会直接拒绝启动。
图片全裂 / 404CDN_BASE_URL 填错了。本地驱动下必须是 http://你的公网IP/api/files，不是 OSS 域名。
docker compose up 说找不到镜像compose 文件里只有 image: 没有 build:，必须先跑 ./deploy/scripts/build.sh。
构建秒退且没输出别用 docker compose build，用 ./deploy/scripts/build.sh（compose 的构建路径在某些环境会因 gRPC 会话头直接失败）。
拉镜像超时/etc/docker/daemon.json 里的镜像加速没配，或者配完没 systemctl restart docker。
进度条转半天然后一次刷完SSE 被 nginx 缓冲了，检查 deploy/nginx/snippets/app-locations.conf 里那条 events 路由是否还在通用 /api/ 之前。
nginx 502app 重启换了容器 IP。docker compose restart nginx。
中文变方块镜像里少了 fonts-wqy-zenhei，按 Dockerfile 里的注释补。

看日志

docker compose logs -f nginx    # 访问日志，含 upstream 耗时
docker compose logs -f cron     # 夜间备份与对账
